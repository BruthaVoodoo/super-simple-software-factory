**Goal:** A user can navigate from a run list to a failed phase, its evidence, its changed files, and its next action — without opening the SQLite database manually.

**Architecture:** The trace/API contract is FROZEN FIRST and documented (`docs/visualizer-contract.md`), enforced by Python contract tests that pin the exact columns and API routes the UI reads. Deterministic fixture traces are generated by a committed script (`scripts/fixture-trace.py`, dev recipe `just fixture-trace`) covering the five canonical run shapes. The UI work then wires the post-M1 trace facts the components don't show yet (repair summaries, quality events, changed files, next actions) and finishes with responsive, accessibility, and typography passes. Backend trace code does not change in M5.

**Tech Stack:** Vue 3 + vite + bun server (existing); the Python harness for contract tests and fixture generation; vue-tsc/oxlint for UI source gates.

**Spec:** `docs/superpowers/specs/2026-09-12-factory-evolution-design.md`, section "M5 — Redesign the visualizer UX" (the eight session-detail questions, required sequence 1–6, exit condition) and rule 10 ("Do not redesign the visualizer against an undocumented or changing trace contract").

## Global Constraints

- The trace/API contract is frozen BEFORE UI revision; if a change to trace code is ever needed, the contract doc is updated in the same task and the contract tests are updated deliberately — never silently.
- No new Python test framework; no playwright/CI (M6 decides release tooling). UI source gates are the existing `vue-tsc --noEmit` + `oxlint`.
- No new runtime dependencies for the factory; the visualizer's package.json gains no new dependencies.
- Offline lanes stay credential-free and network-free; UI validation against a live server happens OUTSIDE the lanes (recorded in the acceptance report).
- No `git add -A` in the source checkout; scratch targets only; never touch the historical example worktree.
- The 8 questions (spec) drive every UI task: run status; failing phase; failure cause; what changed; gate evidence; quality results; cost; next actions.

## Decisions that make this plan executable

### A. The contract is what the UI reads, written down and pinned by tests

`docs/visualizer-contract.md` documents: the 7 tables with the exact columns the UI depends on; the API surface (`/api/health`, `/api/sessions`, `/api/sessions/:adw_id`, `/api/sessions/:adw_id/events`, `/api/sessions/:adw_id/archive`, static SPA fallback); status enums (`queued/running/success/fail` phases, `running/success/fail/not_accepted` sessions); the `started_at/ended_at` span columns; `payload_json` shapes for `agent_start` (incl. M4's `session_continued`), `tool_call` (incl. `quality:*` rows), `repair_summary`, `handoff`. Contract tests pin: (a) a live `Tracer` schema has EXACTLY the documented column set per table; (b) `server/index.ts` registers exactly the documented routes (a source scan — textual but honest, plus a live-server check happens at acceptance time outside lanes).

### B. Fixture traces are code, deterministic, and cover the five canonical shapes

`scripts/fixture-trace.py TARGET_DIR` builds five runs in one trace DB via direct `Tracer`/`Run` construction (no agents, no Pi): `success-run` (2 phases, tool span, handoff, quality events, usage), `gate-failed-run` (gate checks rows + violations + repair_summary `gate_exhausted`), `parse-failed-run` (invalid envelope rows, `repair_summary parse_exhausted`), `not-accepted-run` (phases success, `not_accepted` error event, session `not_accepted`... status `fail` with the event), `running-run` (phase mid-flight). IDs, timestamps, and token counts are fixed constants — the same bytes every time except timestamps (documented). Dev recipe `just fixture-trace [DIR]`.

### C. The eight questions map to concrete component changes

| Question | Component change |
|---|---|
| 1 run status | `SessionCard`/header: show `not_accepted` as its OWN state (currently folds into fail) with a distinct chip |
| 2 failing phase | `SessionTrace`: failed phase pinned/expanded by default |
| 3 failure cause | `PhaseDetail`: surface the phase `error`, the last `repair_summary` (sends/attempts/violations), and the final invalid envelope side by side |
| 4 what changed | NEW section: `paths_touched` log events + handoff artifacts + (when present) the `changes.diff` artifact link |
| 5 gates verified | existing gate section: group rows by attempt, show `checks_json` items (item/ok/note) not just the verdict |
| 6 quality results | NEW section: `tool_call` events named `quality:*` rendered as command + exit + duration + output tail link |
| 7 cost | existing token breakdown stays; sessions list total already shows — keep, add per-phase cost from `agent_end` payload |
| 8 next actions | NEW `NextActions` strip computed from run state: running → "watch / `just procs <id>` / `just kill <id>`"; failed → "`just phases <id>`, fix and re-run with `--adw-id <id>`"; not_accepted → name the unmet criterion from the `not_accepted` event payload |

### D. UI source gates and validation

`bun run typecheck` (vue-tsc) + `bun run lint` (oxlint) must pass after every UI task (run by the developer; node_modules require `bun install` — a network op done once outside lanes, recorded in the acceptance report). Validation: walk each of the 8 questions against the fixture traces AND the real example trace; record the walkthrough (answers + where they appeared) in `docs/baselines/m5-acceptance.md`.

```python
"""Fixture traces: deterministic, contract-conformant, five canonical shapes."""
from __future__ import annotations

import sqlite3
import subprocess
import sys
import unittest

from tests.support.environment import child_env
from tests.support.factory import ROOT, FactoryTestCase

FIXTURE_RUNS = ("fixture-success", "fixture-gate-fail", "fixture-parse-fail",
                "fixture-not-accepted", "fixture-running")


class FixtureTraceTests(FactoryTestCase):
    def setUp(self) -> None:
        super().setUp()
        self.out_dir = self.target / "fixtures"
        result = subprocess.run(
            [sys.executable, str(ROOT / "scripts" / "fixture-trace.py"),
             str(self.out_dir)],
            cwd=str(self.target), env=child_env(self.target / ".home"),
            capture_output=True, text=True, timeout=60)
        self.assertEqual(result.returncode, 0, result.stderr)

    def query(self, sql: str, params: tuple = ()) -> list[tuple]:
        with sqlite3.connect(self.out_dir / "fixture.db") as conn:
            return conn.execute(sql, params).fetchall()

    def test_all_five_runs_exist_with_expected_statuses(self):
        rows = dict(self.query(
            "SELECT adw_id, status FROM sessions WHERE adw_id LIKE 'fixture-%'"))
        self.assertEqual(rows, {
            "fixture-success": "success",
            "fixture-gate-fail": "fail",
            "fixture-parse-fail": "fail",
            "fixture-not-accepted": "fail",
            "fixture-running": "running",
        })

    def test_failure_fixture_carries_evidence_the_ui_needs(self):
        # gate fixture: gate rows with checks; repair summary; failed phase
        gate_rows = self.query(
            "SELECT passed, checks_json FROM gate_results WHERE adw_id='fixture-gate-fail'")
        self.assertTrue(any(row[0] == 0 for row in gate_rows))
        self.assertTrue(all(row[1] for row in gate_rows))
        failed_phase = self.query(
            "SELECT status, error FROM phases WHERE adw_id='fixture-gate-fail' "
            "AND status='fail'")
        self.assertTrue(failed_phase and failed_phase[0][1])
        summaries = self.query(
            "SELECT payload_json FROM events WHERE adw_id='fixture-gate-fail' "
            "AND name='repair_summary'")
        self.assertTrue(summaries)

    def test_not_accepted_fixture_names_the_criterion(self):
        rows = self.query(
            "SELECT payload_json FROM events WHERE adw_id='fixture-not-accepted' "
            "AND name='not_accepted'")
        self.assertTrue(rows)
        self.assertIn("reason", rows[0][0])

    def test_success_fixture_has_spanned_tool_calls_and_quality_events(self):
        spans = self.query(
            "SELECT started_at, ended_at FROM events WHERE "
            "adw_id='fixture-success' AND type='tool_call'")
        self.assertTrue(all(started and ended for started, ended in spans))
        quality = self.query(
            "SELECT name FROM events WHERE adw_id='fixture-success' "
            "AND type='tool_call' AND name LIKE 'quality:%'")
        self.assertTrue(quality)

    def test_generation_is_deterministic(self):
        first = sorted(self.query(
            "SELECT adw_id, phase_id, seq, status FROM phases"))
        subprocess.run(
            [sys.executable, str(ROOT / "scripts" / "fixture-trace.py"),
             str(self.out_dir)],
            cwd=str(self.target), env=child_env(self.target / ".home"),
            capture_output=True, text=True, timeout=60)
        second = sorted(self.query(
            "SELECT adw_id, phase_id, seq, status FROM phases"))
        self.assertEqual(first, second)
```
